WHY FILE SIZE MATTERS

Smaller images are easier to use

Image dimensions and file size solve different problems. A large file takes more space to store and can take longer to upload, share or transfer over a network. Some websites and apps also set file-size limits. Reducing the encoded file size can help meet those needs without changing its pixel dimensions, though the best result depends on the image and format.

PICK THE RIGHT OUTPUT

JPG, PNG and WebP

The best format depends on the image and where you plan to use it. Changing formats can affect appearance, transparency and file size.

JPG / JPEG

Photographs and complex scenes

JPG uses lossy compression and does not support transparency. A lower quality setting can reduce file size, but may add visible artefacts. This tool composites transparent areas over the background colour you choose.

PNG

Transparency and crisp graphics

PNG uses lossless compression, so it preserves pixel values rather than using a JPG-style quality setting. It is often useful for transparent graphics, but photographs saved as PNG can be large. This tool does not offer a separate PNG compression level.

WebP

A modern web image format

WebP supports lossy and lossless encoding, and can carry transparency. This tool uses browser canvas encoding; its quality control applies to lossy encoding. Browser support and resulting size depend on the browser and image.

TWO APPROACHES

Lossy and lossless compression

Lossy compression removes some image information to make a smaller encoded file. The change can be subtle or visible depending on the image and encoder settings; repeatedly re-saving a lossy image can introduce further changes. JPG is lossy, and WebP can be encoded in lossy or lossless modes.

Lossless compression stores the image pixels without discarding image information, although the file's representation may be more compact. PNG uses lossless compression. If a PNG is already efficiently encoded, re-encoding it may not reduce its size. This tool uses the browser's PNG encoder and does not provide a separate PNG compression level.

QUALITY WITHOUT GUESSWORK

How to choose image quality

For JPG or WebP output, the quality control changes the encoder's quality hint. It is not a promise of a particular visual score or file-size reduction. A lower setting often makes a smaller file, but may make edges, fine texture or gradients look worse.

Start at the default, compare the result at the size you intend to use, and adjust only if needed. For text, logos and sharp illustrations, check edges closely. The browser's encoder may produce different results from other software.

↔

Dimensions are not file size

Dimensions count an image's pixels, such as 2400 × 1600. File size counts the bytes needed to store it. This tool keeps the pixel dimensions unchanged; compression changes how those pixels are encoded.

A NOTE ABOUT RESULTS

Why an image may not get smaller

A format conversion or re-encoding is not always more compact. Some common reasons include:

  • 1The original is already optimized. Re-encoding a well-compressed JPG or WebP may save very little, or add bytes.
  • 2PNG uses a different approach. It is lossless, and a JPG-like quality slider cannot shrink it. Photographic PNGs can remain large.
  • 3The selected format fits poorly. Converting simple graphics or photographs to a different format can increase the output size.
  • 4Canvas re-encoding changes the file. Browser encoders and their settings differ; the new file is not guaranteed to beat the source.

If the result is larger, the tool says so and offers the original file. You can still preview and download the newly encoded image if you prefer its format or appearance.

BEFORE YOU START

Supported files and limitations

Supported input

Still JPG/JPEG, PNG and WebP images, up to 12 MB and 12 megapixels per file. Animated WebP and GIF, SVG and HEIC are not supported.

Browser resources

Image decoding needs memory in addition to the file's size. A 12-megapixel image can still exceed available memory on a constrained device, even when its file is below the limit.

Orientation and metadata

Images are decoded and re-encoded by your browser. Orientation handling depends on the browser's image decoder. Export removes source metadata, including EXIF information.

Browser support

Use a current browser with JavaScript, Web Workers and Canvas support. If background canvas processing is unavailable, the tool uses a smaller main-thread fallback limited to 4 megapixels; larger images need background-processing support. Available output formats and results vary across browsers.

GOOD TO KNOW

Frequently asked questions

Are my images uploaded or stored?

The compressor reads your chosen image in this browser and creates its output locally. It does not upload the image to an image-processing service or store it in site local storage. The hosting provider still receives ordinary website requests, which may be logged under its own practices. See the Privacy Policy.

Will compressing an image always make it smaller?

No. The original may already be efficiently encoded, or the chosen format and browser encoder may produce a larger file. The tool compares actual byte sizes and offers the original when the new output is larger.

Does the quality slider work for PNG?

No. The slider is for lossy JPG and WebP encoding. PNG is encoded using the browser's PNG encoder, and this tool does not expose a PNG compression-level control.

Will my image remain transparent?

PNG and WebP can preserve transparency when the browser supports the selected output. JPG has no transparency: when you choose JPG, the transparent parts are placed over the background colour shown in the tool.

Does the tool keep the original image dimensions?

Yes. The tool re-encodes the image without resizing it. Pixel dimensions and file size are different things: smaller encoded size does not mean fewer pixels.

What happens to EXIF and other metadata?

The browser exports a new image from decoded pixels, so source metadata such as camera details, timestamps and GPS location is not included in the output. Some browsers may handle orientation differently while decoding; inspect the preview before downloading.

Why did my file fail to load?

Check that it is a valid, still JPG, PNG or WebP image no larger than 12 MB or 12 megapixels. Animated files, corrupted data, unsupported encodings, or limited browser memory can prevent processing. Try a current browser or a smaller image copy.

Can I compress several images at once?

Not at the moment. The tool processes one image at a time so you can review each result before downloading it.
